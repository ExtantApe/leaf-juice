## A. Network and web (K298)
1. Medium: `MapGateway.workOutMapAccess` reads `lp user … permission check` through `ask()`, which collects every server
   line including chat, and `LuckPermsText.checkResult` takes the first `Result:\s*(\w+)` anywhere. A player who types
   `Result: true` during the check sees every world's map for 5 minutes; two checks at once can read each other's answer.
   Fix: accept only LuckPerms' own line shape after a header naming this uuid and permission, not chat; run checks one at a time.
2. Low-medium: `/map/` keeps serving while BlueMap listens on every address; the app only warns. Fix: refuse unless
   `onlyThisMac`.
3. Low: the pack-check pass header goes to any checked address and survives redirects. Fix: only for the own pack host; no
   redirects.
4. Low: `PackGate.admits` reads the whitelist (up to 4 MB) and the log tail before checking a request has player headers.
   Fix: return false first when there are none.
Safe: both listeners on 127.0.0.1 with local-only acceptance and limits; constant-time tokens; no traversal; LinksWeb's CSRF,
cookies, CSP and escaping; console arguments through `PluginCommandWire`; the MCP server is stdio-only with read-only tools
and `suggest`.

## B. Processes and file writes (K300)
1. **High:** `start()` awaits external-server detection, preflight and `applyPending` while the state stays `.stopped`, and
   `launch()` doesn't re-check. Two clicks start two JVMs (the second fails on `session.lock`, and its exit marks the server
   crashed while the first keeps running untracked); Start during `applyRename`'s restore point boots the server mid-rename.
   Fix: a per-server busy state set before the first await, checked everywhere that starts or changes a stopped server.
2. Medium: ICU's `$` matches before a final newline, so `"Steve\n"` passes the name patterns; the invite sheet trims spaces
   only. The console then gets two lines (an invite without `--json`, which can print the code to the log). Same for world
   seeds. Fix: `\z`, and reject newlines in `PluginCommandWire.encode` and `send`. Also escape `\r` in `PropertiesDocument`.
3. Medium-low: the Configs page sends raw `whitelist add` and `op`, skipping Usher and the online-mode check.
4. Low: load, unload, remove, clone and modify world commands don't validate the world name.
5. Low: the allowlist read-back matches by name or uuid, so it can remove the wrong person.
6. Low: LuckPerms group read-backs can be faked from chat (same `ask()` cause as A1).
7. Low: a player restore while the state is external, starting or stopping can be overwritten by the server.
8. Low: restore deletes `player.dat` before copying. Fix: copy to a temp file, then replace.
9. Low: `latest.log` and old logs are read whole. Fix: tail with a byte cap.
10. Low: test copies don't fence off plugins on a shared outside database.
Safe: no shell anywhere (argument arrays); output and answer caps; once-secrets; pid plus folder checks; atomic config saves
with history and staged merges; Usher-routed access; validated delete with backup first; Lab on 127.0.0.1.

## C. Untrusted input and supply chain (K299)
1. Medium: `ExpectedHashes.verify` passes when no hash is given, so Spiget, Jenkins, web sources and digest-less GitHub assets
   install unchecked, and the auto-update loop accepts some of them. Fix: fail closed without a hash; `.auto` only for sources
   that publish one.
2. Medium: console waiters match any line by substring, chat included (`saved the game` during `save-all flush` lets a copy
   start early), and `uuidPattern` isn't anchored (a chat line can misfile a player's safety snapshot). Fix: ignore chat
   lines; anchor the pattern.
3. Low-medium: a Modrinth hash match adopts that project as the update source without asking.
4. Low: Fill's `file.name` is used unsanitized as the jar path. Fix: `lastPathComponent`, `.jar` only.
5. Low: Hangar's `externalUrl` and Jenkins sources open without a scheme check. Fix: `PluginLinks.clean`.
6. Low: a crafted gzip header crashes the NBT reader (offset past the end). Fix: bounds check.
7. Low: chat creates issues (a fake "critical"), rule records aren't capped, and web searches can include chat text.
8. Low: `Tool.run` has no output cap or timeout; `unzip -p` runs on fresh untrusted jars; pack size trusts the zip's sizes.
9. Info: SHA-1s of unidentified jars, private ones included, go to Modrinth on refresh with no setting.
Safe: pinned upgrade-tool hash; plugin installs by `lastPathComponent` with plugin.yml checks; pack archives resolve links and
stay inside the pack; links cleaned to http(s); no ATS exceptions; no telemetry; no secrets outside the Advisor.

## Common cause
Six findings (A1, B6, C2, C7 and the waiters) come from reading chat as if it were server output. One shared rule (a line
whose message starts with `<name>` or came from the chat thread is never a server answer) fixes them together.
